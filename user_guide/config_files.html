Configuration files

A configuration file describes the channels of the modules of a bench, so that you do not have to enter them again each time a plugin starts. It is a TOML file, and it works as a state manager built into the plugin and dedicated to DAQmx: the state manager of the Dashboard cannot restore the channels of a plugin, which exist only once it has started, whereas a configuration describes them. Each file is a configuration, and the plugin offers the list of the configurations in a drop-down menu, so that the choice is saved with the preset of the plugin.

Where the files are

All the files live in the daqmx folder of the PyMoDAQ system configuration folder (for instance C:\ProgramData\.pymodaq\daqmx on Windows), so that every user of the computer sees the same configurations. A configuration is named by its suffix: config_daqmx_<suffix>.toml is the configuration <suffix>, and config_daqmx.toml is the configuration shown as default. When you save a configuration from the plugin, you give the suffix only.

description = "The bench of config_daqmx_bench.toml, in the current format"

product = "cDAQ-9174"

Format

version

Required. The version of the format, 1. Another value is refused.

description

Free text.

[devices.<name>]

Optional, one table for each device (a cDAQ chassis for instance). product is its product type, which is informative.

[modules.<name>]

One table for each module, named as in NI MAX (cDAQ1Mod3, or Dev1 for a board). The name of a channel is its module and its key: [modules.cDAQ1Mod3.ai.ai0] is the channel cDAQ1Mod3/ai0, so the module of a channel is the device its name starts with. product is the product type of the module, informative. frequency is optional: the sampling frequency of the module in Hz, a positive integer. The generic viewer acquires each module with its own task, so each has its own frequency (with an external clock, the highest frequency of that clock). clock is optional: a terminal such as /cDAQ1/PFI1 or /cDAQ1Mod1/ai/SampleClock (the clock of another module); without it the module uses its own clock.

[modules.<name>.trigger]

Optional: what starts the task of the module; without it the task starts at once. type is digital edge (terminal, such as /cDAQ1/PFI0, and edge) or analog edge (channel, a channel of the module such as cDAQ1Mod3/ai0 or a dedicated analog trigger terminal such as /Dev1/APFI0, level in volts, inside the range of the channel, and edge). edge is rising (the default) or falling.

[modules.<name>.ai.<key>]

One table for each analog input channel. The channel is <module>/<key> (cDAQ1Mod3/ai0) and the order of the tables in the file is the order of the data of an acquisition. type selects the kind of channel and its other keys. info is a free note, kept when the file is saved again. read is optional and true by default: with false the channel is in the task but its samples are not in the data (to watch a trigger without reading it). A key that does not belong to the type is an error, so that a typo cannot go unnoticed.

The names of the keys are the names of the arguments of the channels of the Python API (see Reference), and a value that is a constant of the driver is written with its name.

Default values

Only type is required in a channel. A key you leave out takes the default value of the table above, which is the default of the Python API, and nothing tells you when it happens. In particular, a voltage channel without min_val and max_val is measured on the range -10 V to 10 V, and a thermocouple channel without them on 0 to 100 degrees. The range is passed to the driver, which may round it to a range the module supports, so write the ranges you rely on explicitly:

[modules.cDAQ1Mod3.ai.ai0]
type = "voltage"        # measured from -10 V to 10 V, RSE not set: DEFAULT terminal configuration

[modules.cDAQ1Mod3.ai.ai1]
type = "voltage"
min_val = -1.0          # explicit, nothing is left to the defaults
max_val = 1.0
terminal_config = "RSE"

terminal_config = "DEFAULT" lets the driver choose the terminal configuration of the module. The settings tree of the plugin shows the values that were read, defaults included, once a configuration is chosen.

Mistakes

A file the plugin cannot use is refused with a message that names the file and the entry, for instance:

config_daqmx.toml: [cDAQ1Mod3.ai.ai0] unknown terminal_config 'FLOATING', expected one of ['DEFAULT', 'RSE', ...]

Files of the previous versions

The files of the previous versions of the plugin (a NIDAQ_Devices table with DEVICE01 and MODULE01 tables) can still be read, with their voltage, current and thermocouple channels. Choosing such a file and saving it under a new suffix writes it in the current format; the original is never modified. The keys were renamed: value_min and value_max became min_val and max_val, termination became terminal_config, and thermo_type became thermocouple_type. The keys source and analog_type are replaced by type.
